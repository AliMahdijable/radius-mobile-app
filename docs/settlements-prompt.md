كتبته الجلسة التي بنت الميزة على الخادم والويب، فجر 2026-10-03 بتوقيت بغداد.

## ٠. المهمّة

أنت تكمل ميزة «تسوية الحساب» في `mobile-app-v2`. المرجع الحيّ لكلّ سلوكٍ
ونصٍّ هو الويب على `https://rad.mysvcs.net/v2/reports/settlements`، فما يفعله
الويب يفعله التطبيق بتصميم التطبيق.

1. اجعل كود `d4bb6ed` يُبنى ويمرّ باختبارات المستودع.
2. أكمل ما ينقص التطبيق ليطابق الويب: معاينة البداية، وأرشيف التسويات في
   الصرفيات والتقرير الماليّ واللوحة، وسجلّ النشاط.
3. اترك الخادم والويب كما هما. إن رأيت أنّ الواجهة البرمجيّة تحتاج تغييراً
   فتوقّف واسأل المستخدم، لأنّ الخادم في مستودعٍ آخر وكلّ إعادة تشغيلٍ له
   تقطع الخدمة نحو ٤ ثوانٍ.

## ١. الميزة وقرارات المستخدم

هذه القرارات محسومة، فلا تُعِد فتحها.

**الفكرة.** «الصندوق» هو النقد الذي يجب أن يكون في يد المدير الآن:

```
الصندوق = المُرحَّل من التسوية السابقة + الإيراد الواصل − الصرفيات
```

- **الإيراد الواصل** هو «النقد المستلم» في التقرير الماليّ بالتعبيرات نفسها:
  التفعيل النقديّ (والجزئيّ بالمبلغ المدفوع منه فقط) مع تسديد الديون
  (`PAYMENT_ADD` و`DEBT_PAY` و`BALANCE_DEDUCT`).
- **الديون الجديدة** (التفعيل غير النقديّ و`BALANCE_ADD`) تُعرض للعلم فقط
  ولا تدخل الصندوق.
- حركات المدراء الفرعيّين (`target_type = MANAGER`) خارج الصندوق، كما هي
  خارج التقرير الماليّ.

**التسوية حدٌّ فاصل، ولا يُحذف فيها شيء.** حين يستلم المدير النقد ويضغط
«تسوية» يُحفظ سندٌ مرقّم (#1، #2…) فيه لقطةٌ ثابتة للأرقام ولحصّة كلّ موظّف،
ويبدأ صندوقٌ جديد من الصفر أو من المُرحَّل. أمّا سجلّ الحركات فلا يُمسّ.

**القرارات:**

| الموضوع | القرار |
|---|---|
| النطاق | الحساب كاملاً، مع تفصيل حصّة كلّ موظّف (`collectors`) |
| الفرق بين المتوقّع والمستلَم | يُرحَّل للتسوية التالية: `carried = expected − received` (وقد يكون سالباً) |
| مَن يسوّي | المدير، أو الموظّف الذي يملك `settlements.create` |
| مَن يرى | المدير، أو الموظّف الذي يملك `settlements.view` |
| الإلغاء | للمدير صاحب الحساب وحده، ولآخر سجلٍّ فعّال فقط. يبقى الملغى مشطوباً بسببه، ولا يُعاد استعمال رقمه |
| الصرفيات المسوّاة | مقفلة: تعديلها أو حذفها يُرجع `409 EXPENSE_LOCKED`. ولتصحيحها يُلغى آخر تسوية أو تُضاف صرفيةٌ جديدة |
| انتماء الحركة | بترتيب التسجيل، لا بالتاريخ المكتوب. فالصرفية التي تُدخَل بعد التسوية بتاريخٍ سابق تذهب للفترة الجديدة، وتحمل شارة «بتاريخ …» (`backdated`) |
| البداية | يختار المدير من أين يُحسب الصندوق أوّل مرّة: بداية الشهر، أو بداية اليوم، أو الآن، أو تاريخاً آخر، مع رصيدٍ افتتاحيّ اختياريّ (فكّة موجودة أصلاً) |
| **الأرشيف** (10-03) | ما غطّته تسويةٌ فعّالة يختفي من شاشات «الآن»: إيراد اللوحة، والصرفيات، والتقرير الماليّ. ويبقى في القاعدة، ويُرى بزرّ «مع الأرشيف» أو من السند. الديون لا تتأثّر، والبداية وحدها لا تُخفي شيئاً |

**لماذا وُجدت معاينة البداية:** حين جرّب المستخدم البداية بلا معاينة قال
«التصميم يدوخ… ما أعرف شنو أسوّي». كان يختار تاريخاً ولا يرى أثره إلّا بعد
البدء، فيلغي ويعيد حتى يفهم. لذلك يرى الآن ما سيكون في الصندوق قبل أن يبدأ.

## ٣. عقد الواجهة البرمجيّة

### قواعد عامّة

- **الهويّة من التوكن وحده** (`strictAuth`). يُرسَل التوكن في الهيدر
  `Authorization: Bearer`، ولا يُرسَل `adminId` في الجسم أبداً.
- **الكتابة** (`open` و`settle` و`void`) تفحص توكن SAS حيّاً بلا كاش
  (`freshAuth`). فإن رجع 401 فالجلسة انتهت، ويُطلب من المستخدم أن يدخل من جديد.
- **شكل الخطأ:** `{ success:false, code, message, ...extra }`. الـ`message`
  عربيّ جاهز للعرض كما هو. وأخطاء المنطق كلّها 4xx، لأنّ Cloudflare يستبدل
  صفحات 5xx. فالـ5xx يعني عطلاً غير معروف.
- **أخطاء الصلاحيّة:**
  - `401` بلا توكن.
  - `403 PERMISSION_DENIED` ومعه `{ permission }`.
  - `403 EMPLOYEE_ACCESS_DENIED` لموظّفٍ معطّل.
- **المبالغ** أرقام JSON بالدينار العراقيّ، مقرّبةٌ لمنزلتين. والصندوق قد يكون
  **سالباً**، فاعرضه بإشارته (`settleMoney` في `settle_widgets.dart`).
- **الأوقات** بصيغة ISO-8601 بتوقيت UTC، مثل `2026-10-02T22:33:42.000Z`.
  اعرضها بتوقيت بغداد (+03:00 ثابت، بلا توقيتٍ صيفيّ).

### المسارات

| المسار | الصلاحيّة | الوظيفة |
|---|---|---|
| `GET /api/v2/settlements/current` | view | الصندوق الآن، وهو نفسه معاينة التسوية |
| `GET /api/v2/settlements/preview-start?start=now\|YYYY-MM-DD` | view | معاينة البداية قبل إنشائها، قراءةٌ فقط |
| `GET /api/v2/settlements/movements?settlement=current\|<id>&limit=&offset=` | view | حركات الصندوق: النقد الداخل والصرفيات فقط |
| `GET /api/v2/settlements?limit=&offset=` | view | السجلّ: البداية والتسويات والملغاة، الأحدث أوّلاً |
| `GET /api/v2/settlements/:id` | view | سندٌ واحد مع حصص المنفّذين المجمّدة |
| `POST /api/v2/settlements/open` | create | بداية الحساب |
| `POST /api/v2/settlements` | create | التسوية |
| `POST /api/v2/settlements/:id/void` | **المدير وحده** | إلغاء آخر سجلٍّ فعّال |

`view` تعني `settlements.view`، و`create` تعني `settlements.create`. والمدير
نفسه يملك الصلاحيّات كلّها.

### النماذج

**السند** (`Settlement`). يرجع في السجلّ، وفي `head`، ومن `open` و`settle` و`void` و`:id`:

```jsonc
{
  "id": 7, "kind": "settlement",            // أو "opening" للبداية
  "number": 1,                               // null للبداية
  "status": "active",                        // أو "voided"
  "period_start_at": "…Z", "cut_at": "…Z",
  "opening_balance": 0,                      // المُرحَّل الداخل في هذه الفترة
  "cash_activations": { "sum": 0, "count": 0 },
  "debt_payments":    { "sum": 0, "count": 0 },
  "cash_in": 0,                              // مجموع السطرين السابقين
  "expenses":  { "sum": 0, "count": 0 },
  "new_debts": { "sum": 0, "count": 0 },     // للعلم فقط
  "expected_amount": 720000, "received_amount": 720000,
  "carried_amount": 0,                       // expected − received
  "note": null, "admin_username": "…",
  "acting_employee_id": null, "acting_employee_username": null,
  "voided_at": null, "voided_by": null, "void_reason": null,
  "created_at": "…Z",
  "range": { "from_activity_id": 0, "to_activity_id": 0, "from_expense_id": 0, "to_expense_id": 0 },
  "collectors": [ /* في :id وsettle وvoid فقط */ ]
}
```

**حصّة المنفّذ** (`collector`). تحمل `employee_id: null` حين المنفّذ هو المدير نفسه:

```jsonc
{ "employee_id": 12, "username": "emp_user", "name": "الاسم الكامل",
  "cash_activations": {"sum":0,"count":0}, "debt_payments": {"sum":0,"count":0},
  "expenses": {"sum":0,"count":0}, "net_amount": 435000 }
```

يأتي المدير أوّلاً، ثمّ الموظّفون من الأكبر صافياً. ومن لم يقبض نقداً ولم
يصرف شيئاً لا سطر له.

**`current` حين لم يبدأ الحساب:**

```jsonc
{ "started": false, "today": "2026-10-03", "month_start": "2026-10-01",
  "can_settle": true, "can_void": true }
```

`today` و`month_start` بتوقيت بغداد. استعملهما لخيارَي «بداية اليوم»
و«بداية الشهر» بدل ساعة الجهاز.

**`current` بعد البداية:**

```jsonc
{ "started": true,
  "head": { /* Settlement: آخر سجلٍّ فعّال، بدايةٌ أو تسوية */ },
  "period": { "start_at": "…Z", "until_at": "…Z" },
  "cut": { "head_id": 7, "activity_id": 912345, "expense_id": 611 },
  "totals": { "opening_balance": 0, "cash_activations": {…}, "debt_payments": {…},
              "cash_in": 0, "expenses": {…}, "new_debts": {…}, "expected_amount": 0 },
  "collectors": [ … ], "can_settle": true, "can_void": true }
```

- `can_void` صحيحةٌ للمدير وحده، و`can_settle` للمدير أو لمن يملك `settlements.create`.
- **`cut` هو الحدّ:** ما تراه في المعاينة هو بالضبط ما يُسوّى. أرسله كما هو
  عند التأكيد. والحدّ يقف عند الحركات التي عمرها ٥ ثوانٍ فأكثر، فما سُجّل في
  آخر لحظة يذهب للفترة التالية.

**`preview-start`:**

```jsonc
{ "start": "2026-08-01", "start_at": "2026-07-31T21:00:00.000Z",
  "totals": { "cash_activations": {…}, "debt_payments": {…}, "cash_in": 0,
              "expenses": {…}, "new_debts": {…}, "expected_amount": 720000 },
  "collectors": [ … ] }
```

⚠️ `expected_amount` هنا **بلا** الرصيد الافتتاحيّ. فالمعروض للمستخدم هو
`expected_amount + opening` كما يكتبه في الحقل.

**حركة صندوق** (`movements.items[]`). الاستجابة `{ items, has_more, limit, offset }`،
والحدّ الأقصى لـ`limit` هو 500 (والافتراضيّ 100):

```jsonc
{ "source": "activity", "id": 912340, "kind": "cash_activation",  // أو debt_payment أو expense
  "direction": "in",                                              // expense ⇒ "out"
  "amount": 25000, "created_at": "…Z",
  "subscriber": "ali123", "package_name": "…", "description": "…",
  "expense_date": "2026-09-30 00:00:00", "backdated": true,       // للصرفيات فقط
  "employee_id": 12, "employee_username": "emp_user", "employee_name": "الاسم الكامل" }
```

### الأجسام

```jsonc
// POST /open
{ "start": "now" | "YYYY-MM-DD", "opening_balance": 0, "note": "…" }

// POST /api/v2/settlements
{ "cut": { "head_id": 7, "activity_id": 912345, "expense_id": 611 },  // من current كما هو
  "expected_amount": 720000,     // الرقم الذي رآه المستخدم
  "received_amount": 720000,     // ما استلمه فعلاً، 0 أو أكثر
  "note": "…",
  "idempotency_key": "k8…"       // [A-Za-z0-9_-]{8,64}، مفتاحٌ واحد لكلّ فتحة شيت
}

// POST /:id/void
{ "reason": "سببٌ من ٣ أحرف فأكثر" }
```

- `settle` يُرجع `{ success, duplicate, message, data }`. و`duplicate: true`
  يعني أنّ المفتاح نفسه سبق أن نجح، فالسند المُعاد هو الأوّل نفسه، ولم تُنشأ
  تسويةٌ ثانية.
- `open` و`void` يُرجعان `{ success, message, data }`.

### رموز الأخطاء

| الرمز | HTTP | متى | ماذا تفعل الواجهة |
|---|---|---|---|
| `NOT_INSTALLED` | 409 | الهجرة لم تُشغَّل (لم يعد يقع) | بطاقة «لم تُفعَّل بعد» |
| `BAD_START` | 422 | تاريخٌ غير صالح، أو قادم، أو قبل 2025-01-01 | الرسالة |
| `BAD_AMOUNT` | 422 | مبلغٌ غير صالح | الرسالة |
| `ALREADY_STARTED` | 409 | البداية موجودة | أعد تحميل `current` |
| `NOT_STARTED` | 409 | تسويةٌ بلا بداية | أعد التحميل |
| `BAD_CUT` | 422 | حدٌّ ناقص أو خارج المدى | أعد التحميل |
| `BAD_KEY` | 422 | مفتاح تكرارٍ غير صالح | خطأ برمجيّ |
| **`STALE`** | 409 | تغيّرت الأرقام منذ فتح المعاينة | الجسم فيه `current` جديد: حدّث الشيت به واطلب تأكيداً جديداً (منفَّذ في `settle_sheet.dart`) |
| **`HEAD_CHANGED`** | 409 | سُجّلت تسويةٌ أخرى للتوّ | مثل `STALE` |
| `BUSY` | 409 | عمليّةٌ أخرى على الصندوق نفسه | «أعد المحاولة بعد لحظات» |
| `OWNER_ONLY` | 403 | موظّفٌ يحاول الإلغاء | أخفِ زرّ الإلغاء أصلاً (`can_void`) |
| `NEED_REASON` | 422 | سبب الإلغاء أقصر من ٣ أحرف | الرسالة |
| `NOT_LAST` | 409 | ليس آخر سجلٍّ فعّال | الإلغاء لآخر سجلّ فقط |
| `ALREADY_VOIDED` | 409 | ملغى سابقاً | أعد التحميل |
| `NOT_FOUND` / `BAD_ID` | 404 / 422 | سندٌ غير موجود | الرسالة |
| `EXPENSE_LOCKED` | 409 | تعديل صرفيةٍ مسوّاة أو حذفها | الرسالة، ومعها `settlement_number` |

## ٤. الأرشيف — العقد

| المسار | السلوك |
|---|---|
| `GET /api/reports/finance` | يُخرج المؤرشف **افتراضيّاً** من الاستعلامات كلّها (الأرقام، والسلسلة، وآخر الحركات، والصرفيات). ومع `include_archived=1` يرجع كلّ شيء. والوصف في `data.archive` |
| `GET /api/admin/expenses` | القائمة ومجموعها بلا المؤرشف افتراضيّاً، و`include_archived=1` يُرجعه. والوصف في `archive` بجوار `expenses` و`total`. وكلّ صرفيةٍ تحمل `settlement_number` (`null` تعني مفتوحة قابلة للتعديل) |
| `GET /api/activities` | **لا يُؤرشَف**، فهو سجلّ تدقيق. لكنّه لا يُرجع `EXPENSE_ADD` إلّا مع `include_expense_logs=1` (انظر ٦-٦) |

```jsonc
"archive": {
  "hidden": true,        // يوجد مؤرشف وهو مخفيٌّ الآن
  "included": false,     // أُرسل include_archived=1
  "settlements": 1,      // عدد التسويات الفعّالة
  "last_number": 1,      // رقم آخر تسوية
  "last_cut_at": "…Z"    // وقتها
}
```

- إن كان `archive` غائباً، أو كان `settlements` صفراً، فلا تعرض شيئاً.
- النسخ الحاليّة من التطبيق تُخفي المؤرشف من الآن، لأنّه السلوك الافتراضيّ
  في الخادم. ينقصها الزرّ والتوضيح فقط.

## ٦. المطلوب، بالترتيب

ادفع بعد كلّ خطوة (انظر القسم ٨).

### ٦-١ اجعله يُبنى

```bash
git pull --ff-only
flutter pub get
flutter analyze
flutter test
```

الكود كُتب بلا مترجم، فتوقّع أخطاء تواقيع: `SheetSegmented` و`SheetQuickChip`
و`SheetSection` و`ToneChip` و`AmountTextField` وسجلّات Dart (records). وكلّ
ملفٍّ يستورد `easy_localization` يجب أن يستوردها مع `hide TextDirection`.
أصلح الأخطاء بأقلّ تغيير، ولا تُعِد تصميم ما يعمل.

### ٦-٢ معاينة البداية (`_startCard`)

انقل `StartCard` من الويب:

1. **العنوان** «ابدأ حساب الصندوق»، وتحته ثلاث خطواتٍ مرقّمة:
   - اختر تاريخ آخر مرّة استلمت فيها نقد الصندوق، أو بداية الشهر.
   - ترى في الأسفل مباشرةً ما وصلك وما صرفته من ذلك التاريخ حتى الآن.
   - اضغط «ابدأ»، ثمّ «تسوية الآن» حين تستلم المبلغ — يُحفظ سندٌ مرقّم ويصير الصندوق صفراً.
2. **الاختيارات الأربعة** موجودة (`_startMode`).
3. **صندوق المعاينة** جديد، تحت الاختيار وقبل حقل الرصيد الافتتاحيّ:
   - أضف `SettlementsApi.previewStart(start)` ونموذج `StartPreview`.
   - اطلبها كلّما تغيّرت قيمة البداية وكانت صالحة (`now` أو تاريخاً).
   - أبقِ النتيجة السابقة باهتةً أثناء الجلب، وتجاهل الردود المتأخّرة التي
     تخصّ اختياراً سابقاً.
   - المعروض: «‹البداية› حتى الآن سيكون في الصندوق»، ثمّ المبلغ =
     `expected_amount + opening` (أحمر إن كان سالباً)، ثمّ التفصيل: تفعيلات
     نقديّة (+)، وتسديد ديون (+)، وصرفيات (−)، ورصيد افتتاحيّ (+) إن وُجد.
   - إن لم توجد حركات: «لا حركات في هذه الفترة — اختر تاريخاً أبعد لتحسب ما مضى.»
   - بلا تاريخ: «اختر التاريخ لترى ما في الصندوق منذ ذلك اليوم.»
4. **نصّ زرّ البدء** في `_footer()`: «ابدأ الحساب من الآن» حين يكون الاختيار
   الآن، و«ابدأ الحساب من هذا التاريخ» في غيره.

### ٦-٣ الأرشيف في شاشة الصرفيات

- `ExpensesApi.list` تأخذ `includeArchived` وتُرجع `archive` أيضاً.
- الشاشة تعرض شريط الأرشيف فوق القائمة، **فقط** حين `archive.settlements > 0`.
  نصّ الشريط كنصّ الويب (`ArchiveBar.tsx`):
  - في «الحاليّة»: «يُعرض ما بعد آخر تسوية (#N · ‹اليوم والتاريخ›) — المسوّى محفوظ في الأرشيف.»
  - في «مع الأرشيف»: «تُعرض كلّ الحركات، ومعها المسوّاة في N تسوية.»
  - رابطٌ إلى «تسوية الحساب»، ومقطّعٌ صغير: «الحاليّة» / «مع الأرشيف».
- في وضع «الحاليّة» قد تكون القائمة فارغة لأنّ كلّ شيءٍ سُوّي. هذا صحيح،
  والشريط يشرحه.

### ٦-٤ الأرشيف في التقرير الماليّ

- `ReportsApi.finance` تأخذ `includeArchived`، و`FinanceReport` يحمل `archive`.
- ضع الشريط نفسه فوق `DateRangeChipBar`، وأعد التحميل حين يتغيّر الوضع.

### ٦-٥ إيراد اللوحة (`hero_revenue_card.dart`)

- `DashboardApi.fetchRevenue` تقرأ `data.archive`.
- حين يكون `hidden` أضف بجوار عنوان الفترة: « · بعد التسوية #N».
- إن عرضت البطاقة يوماً مقارنةً بالفترة السابقة، فأخفِها حين تقع تسويةٌ في
  نافذتها، لأنّ الفترة السابقة مبتورة فتكذب النسبة. الويب يُخفي مقارنة
  اليوم إن وقعت التسوية في آخر يومين، ومقارنة الأسبوع إن وقعت في آخر ١٤ يوماً.

### ٦-٦ سجلّ النشاط (`activity_log_report_screen.dart`)

هذه الشاشة تدمج الصرفيات بنفسها من `ExpensesApi.list`، لأنّ الصرفيات لم تكن
تُسجَّل في `activity_logs`.

- **مرّر `includeArchived: true`.** السجلّ يعرض كلّ شيء، وإلّا اختفت الصرفيات
  المسوّاة من السجلّ بينما بقيت التفعيلات.
- **لا تمرّر `include_expense_logs`.** الخادم صار يسجّل `EXPENSE_ADD` منذ
  الهجرة ٠٠٨، لكنّه يستثنيها من `/api/activities` افتراضيّاً كي لا تظهر كلّ
  صرفيةٍ مرّتين في هذه الشاشة. وإن قرّرت يوماً الاعتماد على سجلّ الخادم،
  فاحذف الدمج من `ExpensesApi.list` أو أزِل التكرار بـ`target_id`.
  وتذكّر أنّ الصرفيات القديمة لم تُسجَّل أصلاً.
- `EXPENSE_EDIT` و`EXPENSE_DELETE` تصل من الخادم دائماً، ولها تسمياتها.

### ٦-٧ الترجمة

- كلّ نصٍّ جديد يُضاف في `ar.json` و`en.json` معاً، تحت `settle.*` أو `exp.*`
  أو مجموعة `archive.*` جديدة.
- لا نصّ ثابتاً في الكود.

## ٧. قواعد التصميم في هذا المستودع

تعلّمها المشروع بالكسر، فالتزمها.

- **التوكنات فقط:**
  - الألوان: `AppColors` و`AppTone` (اختبار `no_raw_colors_test` يمنع الألوان الخامّ).
  - الخطّ: `AppType`، والعائلة تأتي منه، فلا تكتب اسم خطٍّ بيدك.
  - المسافات والزوايا والارتفاعات: `Sp` و`R` و`H`.
  - الأيقونات: `LucideIcons`.
- **زرّ الإجراء الأساسيّ** في شاشةٍ أو شيت هو `SheetFooterBar`. وفي الشاشة
  الكاملة يوضع داخل `ColoredBox(surface)` و`SafeArea(top:false)`. ولا تعطِ
  نصّ زرّ Material لوناً بيدك، فهذا كسر الألوان مرّتين.
- **الشيتات** تُبنى على `DesignSheet` أو `SheetScaffold`. حقل المبلغ داخل
  الشيت هو `AmountTextField`، أمّا في رأس شاشةٍ فالحقل المدمج كشاشة الخصومات.
- **`Row` فيه `Expanded` يسحق النصّ صامتاً** إلى عرضٍ صفر، بلا خطأ ولا فيضٍ
  أحمر. فكلّ `Expanded(child: Text)` بجوار عنصرٍ ثابت يحتاج `maxLines`
  و`ellipsis`، وكلّ صفٍّ تُضيف إليه زرّاً احسب عرضه على ٣٢٠ نقطة. الحارسان:
  `test/text_crush_test.dart` و`test/flex_text_guard_test.dart`.
- **`Spacer` يقتسم المساحة ولا يدفع العناصر.** فقِس قبل أن تصلح.
- **RTL أوّلاً:** `AlignmentDirectional` و`EdgeInsetsDirectional`. والأرقام
  والمبالغ تبقى LTR.
- **الوضع الليليّ:** كلّ `build` يبدأ بـ`Theme.of(context);` كي يُعاد الرسم
  حين يتغيّر الوضع.
- **تبويبات `main_shell` داخل `IndexedStack`** لا تُهدم، فـ`initState` فيها لا
  يعمل إلّا مرّة. والحالة التي تكتبها شاشةٌ وتقرأها أخرى تحتاج `ValueNotifier`.
- **مدخلٌ واحد لكلّ شاشة.** «تسوية الحساب» مدخلها في «المزيد» فقط، فلا
  تضِف اختصاراً في مكانٍ آخر. الرابط داخل شريط الأرشيف ليس مدخلاً جديداً،
  بل سياقٌ يشرح الإخفاء، كما في الويب.
- **حين تنقل شاشة،** عُدّ عناصر التفاعل فيها قبل النقل وبعده.

## ٨. قواعد العمل

1. **اسحب أوّلاً** (`git pull --ff-only`). وإن لم يكن السحب fast-forward
   فتوقّف واسأل قبل أيّ دمج.
2. **commit ثمّ push فوراً** بعد كلّ تعديل إلى `radius-mobile-app` على الفرع
   `main`. أضف الملفّات بأسمائها، ولا ترفع أسراراً: `key.properties`
   ومفاتيح التوقيع وملفّات `.env`.
3. **لا Flutter على السيرفر.** إن كانت جلستك على السيرفر
   (`/home/ali/MyServices Raduis/mobile-app-v2`) فعدّل وادفع فقط، ولا تثبّت
   أدوات بناء. والمستخدم يسحب ويبني ويفحص على الماك. لا تقل «يعمل» قبل فحصه،
   بل قل «دُفع، اسحب وافحص» واذكر الـhash.
4. **لا تغيّر bundle ID ولا مفتاح التوقيع أبداً**، فالتطبيق يحدّث النسخة
   القديمة في مكانها.
5. **رقم النسخة يتبع المتجر.** البناء التجريبيّ لا يرفعه. يُرفع مرّةً واحدة عند
   النشر، بواحدٍ فوق ما في المتجر، وAndroid وiOS على رقم البناء نفسه. الرقم
   الحاليّ في `pubspec.yaml` هو `2.2.6+149`.
6. **لا تكتب على الحساب الحقيقيّ بلا إذن.** البدء والتسوية والإلغاء تُنشئ
   سجلّاتٍ حقيقيّة وسطوراً في سجلّ النشاط، أمّا القراءة فلا بأس بها.
7. **تواصل بالعربيّة** مع المستخدم.

## ٩. ما يفحصه المستخدم على الجهاز

1. **المزيد ← تسوية الحساب:** يظهر الصندوق والحصص والحركات والسجلّ، وتظهر
   التسوية #1 بمبلغ ٧٢٠٬٠٠٠ في السجلّ. افتحها: الحصص، والحركات، والطباعة.
2. **موظّفٌ بلا `settlements.view`:** لا يرى البطاقة في «المزيد».
3. **موظّفٌ بـ`view` بلا `create`:** يرى الشاشة بلا زرّ «تسوية الآن»، ولا زرّ
   إلغاء لأيّ موظّف.
4. **معاينة البداية** على حسابٍ لم يبدأ (مديرٌ تجريبيّ، أو بعد إلغاءٍ بإذن
   المستخدم): غيّر الاختيار فيتغيّر المبلغ، ويطابق بالدينار ما يعرضه الويب
   للاختيار نفسه.
5. **الصرفيات:** «الحاليّة» لا تُظهر المسوّى، و«مع الأرشيف» يُظهره بشارة
   «تسوية #N». وتعديل صرفيةٍ مقفلة مرفوضٌ برسالةٍ واضحة.
6. **التقرير الماليّ:** الوضعان يطابقان الويب للفترة نفسها.
7. **اللوحة:** إيراد الشهر يعرض «· بعد التسوية #N».
8. **سجلّ النشاط:** الصرفيات المسوّاة ظاهرة، ولا تتكرّر أيّ صرفيةٍ جديدة.
9. **الوضع الليليّ والإنجليزيّة وشاشةٌ بعرض ٣٢٠:** لا نصّ مسحوق ولا مفتاح ترجمة خامّ.

## ١٠. معروفٌ ولم يُصلَح، وليس من عمل التطبيق

- `/api/reports/finance` يقبل `user_ids` من الطلب بلا تحقّق ملكيّة، وبدونه
  يجمع المنصّة كلّها. و`/api/reports/account-statement` يبحث بالاسم بلا حصرٍ
  بالمدير. كلاهما عُرض على المستخدم.
- طباعة وصل الويب التلقائيّة يحجبها CSP. أمّا سند التسوية فيطبع من الصفحة الأمّ.
- النسخ المنشورة من التطبيق قبل هذا العمل تُخفي الصرفيات المسوّاة من سجلّ
  النشاط لمن سوّى حسابه، إلى أن تصل النسخة التي تنفّذ ٦-٦.
